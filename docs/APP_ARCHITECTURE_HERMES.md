# Hermes Agent management

Magnus can manage [Hermes Agent](https://github.com/NousResearch/hermes-agent) installations on
managed hosts. Magnus does not run a model or an agent itself: it records desired state, and the
node agent on each host applies that state through the local `hermes` CLI.

The integration is optional. The console shows the Hermes pages only when
`MAGNUS_HERMES_ENABLED=true`, and the agent manages Hermes only when the `hermes` CLI is installed
for `HERMES_USER`.

## Request flow

```text
Console (apps/dashboard)
  /orchestra/* pages, same-origin proxy
        │
        ▼
Server (services/control-api)
  /api/v1/hermes/* (also mounted as /api/v1/orchestra/*)
  desired state, reconcile jobs, audit
        │
        ▼
Node agent (packages/agent) on the host
  /api/v1/hermes/*  →  local hermes CLI
        │
        ▼
Hermes Agent installation and its profiles
```

## Responsibilities

| Component | Responsibility |
| --- | --- |
| Console | Pages for installations, profiles, drift and proxy security, and the embedded Hermes dashboard. |
| Server | Inventory, desired state, reconcile jobs, audit events, and the [Hermes registry](HERMES_REGISTRY.md). |
| Agent | Authenticated local execution: install, update and uninstall Hermes; profile config, tool policy, providers, credential pools, cron, MCP servers, messaging, hooks and API-server settings. |
| Skills catalogue | `packages/skills` holds the skills Magnus publishes to Hermes profiles. |

The server's desired-state API covers skills, tool policies, roles, providers, credential pools,
MCP servers, messaging bindings, cron jobs, plugins, hooks, API-server posture and reconcile jobs.
Not every domain has its own console page; all of them are in the OpenAPI document.

## Console pages

| Route | Shows |
| --- | --- |
| `/orchestra` | Overview and recent reconcile jobs |
| `/orchestra/installations` | Hermes installations per managed node |
| `/orchestra/profiles` | Profiles per installation |
| `/orchestra/web-gateway` | The selected installation's Hermes dashboard, embedded |
| `/hermes-drift` | Desired versus observed skills and installation state |
| `/hermes-security` | Security events from the Hermes dashboard proxy |

The embedded Hermes dashboard is reached over SSH from the console server, never directly from the
browser. Each installation must have an entry in `HERMES_SSH_AUTHORIZATIONS_FILE` that binds the
installation ID and node ID to exact addresses and expected SHA-256 host keys. See
[observability](OBSERVABILITY.md#hermes-proxy-security-events) for the proxy's event log.

## Managed configuration

When the server installs or updates Hermes on a host, it can pass a managed configuration that the
agent writes into the Hermes config:

- `router`: an OpenAI-compatible model router (for example Hive Router) with base URL, model and
  optional API key;
- `hiveMem`: a HiveMem API URL, token and workspace for shared memory;
- `openaiRuntime: codex_app_server`: run OpenAI models through the Codex App Server and a ChatGPT
  subscription. Magnus never copies Codex credentials. Every host keeps its own
  `~/.codex/auth.json`, created with `codex login`, so Codex refreshes its tokens independently
  on each host.

On the server, `MAGNUS_ROUTER_URL` (with `MAGNUS_ROUTER_MODEL` and `MAGNUS_ROUTER_API_KEY`) and
`HIVEMEM_URL` mark those integrations as configured and add them to dependency health.

## Skills

`packages/skills` is the catalogue Magnus publishes to Hermes profiles. Each skill keeps catalogue
metadata in `manifest.json` and a Hermes `SKILL.md` generated by `npm run skills:build`. Hermes
discovers skills in `~/.hermes/skills/`, in the configured `skills.external_dirs`, and in
installed skill bundles. Magnus assigns skills through the node agent; it does not add a central
plugin host. See the
[Hermes skills documentation](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills).

## Plugin API

A Hermes plugin running on a managed host can call the server with its own scoped credentials
when `MAGNUS_PLUGIN_API_ENABLED=true`. Read credentials are listed in
`MAGNUS_PLUGIN_READ_TOKEN_DIGESTS_JSON` and the operator credential in
`MAGNUS_PLUGIN_OPERATOR_TOKEN_SHA256`; the server stores only their SHA-256 digests. A plugin
credential can reach only the routes for its scope.
